# КТ 3. API с базой данных

REST API для блога на Express, Prisma ORM и SQLite. В базе есть пользователи, посты и теги. У пользователя может быть несколько постов, а один тег может относиться к разным постам.

## Запуск

Нужен Node.js 22.12 или новее. Откройте папку `kt03` в VS Code и выполните в терминале:

```bash
npm install
npm run setup
npm start
```

`setup` создает `.env` из `.env.example`, если файла еще нет, генерирует Prisma Client и применяет миграцию. SQLite не требует отдельного сервера: файл базы `prisma/dev.db` создается автоматически.

Адрес API: http://localhost:3000. Для разработки с перезапуском при изменениях: `npm run dev`. Просмотр базы: `npm run db:studio`.

## Маршруты

| Метод | URL | Действие |
| --- | --- | --- |
| GET | `/api/users` | Список пользователей с пагинацией |
| GET | `/api/users/:id` | Пользователь и его посты, новые сверху |
| POST | `/api/users` | Создание пользователя |
| PATCH | `/api/users/:id` | Частичное обновление пользователя |
| DELETE | `/api/users/:id` | Удаление пользователя |
| GET | `/api/posts` | Посты с фильтрацией и пагинацией |
| GET | `/api/posts/:id` | Пост с автором и тегами |
| POST | `/api/posts` | Создание поста |
| PATCH | `/api/posts/:id` | Частичное обновление поста |
| DELETE | `/api/posts/:id` | Удаление поста |

## Проверка запросов

В Postman импортируйте файл `kt03.postman_collection.json`. Запускайте запросы сверху вниз: сначала создается пользователь, затем пост. Их id сохраняются в переменные коллекции автоматически. Последние два запроса удаляют пост и пользователя.

Создание пользователя, `POST /api/users`:

```json
{
  "email": "von@example.com",
  "name": "Von",
  "role": "USER"
}
```

Создание поста, `POST /api/posts` (в `authorId` укажите id созданного пользователя):

```json
{
  "title": "Первый пост про Prisma",
  "content": "Проверка работы API",
  "published": true,
  "authorId": 1,
  "tags": ["Prisma", "Node.js"]
}
```

Теги передаются как массив строк. `connectOrCreate` находит тег по имени или создает новый. Повторы в массиве убираются. При PATCH переданный массив заменяет теги поста; `[]` очищает связи. Если поле `tags` не передавать, связи сохраняются.

Фильтры можно использовать одновременно:

```text
GET /api/posts?search=prisma&published=true&authorId=1&page=1&limit=5
GET /api/posts?published=false
GET /api/users?page=1&limit=5
```

`search` ищет часть заголовка без учета регистра, в том числе на русском. Для ASCII используется Prisma `contains`. В SQLite нет `mode: 'insensitive'`, поэтому для кириллицы заголовки сравниваются в нижнем регистре до подсчета и пагинации. Этот вариант подходит для небольшой учебной базы.

Ответ списка содержит `data` и `meta`:

```json
{
  "data": [],
  "meta": { "total": 0, "page": 1, "limit": 10, "pages": 0 }
}
```

По умолчанию `page=1`, `limit=10`. Размер страницы: от 1 до 100, номер страницы: от 1 до 1000000. `total` и `pages` учитывают фильтры. Если записей нет, `pages=0`. Записи сортируются по дате создания по убыванию, при одинаковой дате — по id по убыванию.

Валидация выполняется через Joi. Для поста обязательны непустой `title` и числовой целый `authorId`. В JSON поле `published` принимает только `true` или `false`, а `authorId` передается числом без кавычек. Для пользователя обязательны `email` и `name`, роль — `USER` или `ADMIN`. Роль здесь хранится как поле модели; авторизация в задание не входит.

Статусы: `200` — чтение/обновление, `201` — создание, `204` — удаление, `400` — неверные данные, `404` — запись или автор не найдены, `409` — повтор email или конфликт связи. Пользователь с постами не удаляется: сначала нужно удалить его посты. Это сохраняет связь из схемы задания.

## Тесты

```bash
npm test
```

Интеграционные тесты поднимают API на свободном порту и применяют миграцию к отдельной временной SQLite-базе. Проверяют все десять маршрутов, фильтры отдельно и вместе, пагинацию, сортировку, общие теги, PATCH, откат неудачных изменений и ответы на ошибки. Основная база приложения не затрагивается.

В GitHub добавляются исходники, миграции, `.env.example` и `package-lock.json`. Файлы `.env`, локальная база и `node_modules` исключены через `.gitignore`.
